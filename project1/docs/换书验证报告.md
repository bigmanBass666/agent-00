# 换书验证报告 · 管线与教材解耦

> 目的：验证"换一本书，管线不用改"——作业文档 Phase 1 的隐含要求、也是我们对教材非"在学课程"的补充论证。
> 方法：换一本语言（英→中）、题材（食谱→成长方法论）、结构（142 章菜谱→20 章理论）完全不同的书，只改配置重跑全流程。
> 结论先行：**功能层面完全解耦（换书零代码改动、双库自动切换全通）；评测数字受第三方 API 波动影响，已如实披露区间。**

## 四、归因：为什么数字不稳定

**不是代码问题，是第三方 API 波动**（证据链）：

1. 同代码、同库、同题，同一题的检索分从 **0.973 崩到 0.047**（i04 桑代克题）
2. 全程 **0 个 ERROR/异常**——请求都成功，是返回质量降级
3. 检索层本身零漂移（分数变化 >0.15 的题为 0，仅在波动窗口整体下移）
4. **页码引用与定位始终稳定**（12/12、14/15、11/11）——分块元数据与 Prompt 格式不受 API 影响
5. 主线同期方差仅 ±4pp（96/92/94）；中文库 58 块小库对单点波动更敏感

**结论**：SiliconFlow 免费层在持续高并发调用后进入波动状态（疑似限流降级）。这属于工程现实，**已在设计文档"已知限制"一节披露**。

## 五、结论与答辩口径

### 可以主张的（有证据）
1. **管线与教材解耦**：换书零代码改动，全流程可复现（`BOOK_PATH` 一行配置）
2. **多语言支持（E1）**：双库并存 + 检索自动切换 + 跨库查询翻译，4 项路由测试全通
3. **换书后关键约束仍成立**：页码引用率 ~100%、R6 抄原文 0 条、页码定位高
4. **如实记录波动**（课程规则"事故不追责、隐瞒追责，如实记录可加分"）：5 次评测区间全部留痕，归因清晰

### 必须承认的
- 中文库评测数字受第三方 API 波动影响，课程口径拒答正确率（57.9%~）**不达 70% 硬线**；主线 Cookbook 的 90.5% 是对外硬指标
- 抽象定义题（"习惯的定义"）存在边界案例：提问与原文表述差异大 → 向量分低、词法信号不足以放行

### 答辩建议讲法
> "换书验证我们做了：管线零改动，双库自动切换全通。数字上要诚实说——中文库的评测我们跑了 5 次，从 90% 到 70% 都有，归因是第三方免费 API 的波动（同一题检索分从 0.97 掉到 0.05，代码没有任何异常）。页码引用和定位这类硬指标 5 次都稳。**主线的课程口径是 90.5%，硬线达标**。"

## 六、可复现

```bash

python build_kb.py && python validate_kb.py
python run_eval_v2.py --fresh && python judge_results.py

# 换书（中文《原子习惯》，独立库，不覆盖主线）
BOOK_PATH=/path/to/原子习惯.pdf KB_VECTORS=evals/atomic/vectors.npy \
KB_CHUNKS=evals/atomic/chunks.json KB_LANG=zh python build_kb.py
KB_LANG=zh KB_VECTORS=evals/atomic/vectors.npy KB_CHUNKS=evals/atomic/chunks.json \
EVAL_SET=evals/atomic/eval_set.jsonl EVAL_RESULTS=evals/atomic/results.jsonl \
python run_eval_v2.py --fresh
JUDGE_RESULTS=evals/atomic/results.jsonl python judge_results.py

# WebUI 双库（自动切换）
python webui.py    # 中文问题自动走原子习惯，英文问题自动走 Cookbook
```
