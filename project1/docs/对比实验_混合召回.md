# 对比实验：混合召回 vs 纯向量召回

> 对应 v2 拓展挑战：「对比实验：用同一教材对比不同技术栈的检索质量」
> 实验日期：2026-10-18
> 评测集：50 条（同一套题、同一判定规则，仅切换检索配置）

## 一、实验设计

**变量**：是否启用 IDF 加权词汇召回（`config.HYBRID_RECALL`）

| 组别 | 配置 | 说明 |
|------|------|------|
| 对照组 | `HYBRID_RECALL=0` | 仅 bge-m3 向量余弦召回 top-20 → reranker top-3 |
| 实验组 | `HYBRID_RECALL=1` | 向量 top-20 + IDF 词汇 top-20，合并去重 → reranker top-3 |

**控制变量**：同一知识库（159 块）、同一 reranker、同一生成模型与 Prompt、同一阈值（0.3）、同一评测集与判定脚本。

**复现命令**：

```bash
cd project1
HYBRID_RECALL=0 python run_eval_v2.py --fresh && python judge_results.py   # 对照组
python run_eval_v2.py --fresh && python judge_results.py                    # 实验组
```

## 二、总体结果

| 指标 | 纯向量（对照） | 混合召回（实验） | 差值 |
|------|--------------|----------------|------|
| 准确率 | 89.3%（25/28） | **89.7%**（26/29） | +0.4pp |
| 拒答正确率 | **86.4%**（19/22） | 85.7%（18/21） | -0.7pp |
| correct | 25 | 26 | +1 |
| wrong | 1 | 1 | 0 |
| hallucinated | 2 | 2 | 0 |
| refuse_correct | 19 | 18 | -1 |
| refuse_wrong | 3 | 3 | 0 |

**结论：整体指标基本持平，差异在统计噪声范围内（50 题，±1 条题即 ±2pp）。**

## 三、逐题差异（净效果为零的真实原因）

两组仅 2 条题判定不同，且方向相反：

| 题号 | 问题 | 纯向量 | 混合召回 | 原因 |
|------|------|--------|---------|------|
| i17 | How many tablespoons are in one cup? | ❌ 误拒答（refuse_wrong） | ✅ 答对 8 tbsp | 正确答案在 p.14-15 的换算表，向量侧 reranker 仅 0.1746；词汇召回因 `tablespoons`/`cup` 全部命中而给出 1.00 的强信号，**绕过阈值交 LLM 判断后答对** |
| v05 | Is it healthy? | ✅ 拒答 | ❌ 答成"Protein Chips and Guacamole 很健康" | 问题无具体对象，但 `healthy` 在大量菜谱页命中，词汇分 1.00 **绕过阈值**；LLM 拿到资料后自行挑了一道菜作答 |

**一救一伤，正好抵消。**

## 四、分析

### 4.1 混合召回确实解决了它被设计来解决的问题
i17 是典型的"表格碎片"查询：向量模型对 `3 tsp | 1 tbsp | 8 tbsp | 1 cup` 这类无句法结构的文本打分极低（0.17），但词汇信号满分。**这验证了引入词汇通道的初衷。**

### 4.2 但它引入了一个未预期的副作用
词汇放行通道的设计是"实词几乎全覆盖 → 值得让 LLM 看一眼"。这个规则默认了"查询有明确对象"，而模糊问题（`Is it healthy?`）恰好没有对象、却能在书里"命中大量实词"——于是被错误放行。

### 4.3 因此本次实验的真正价值不是"证明了混合召回更好"
而是**定位到了一个设计缺陷**：词汇放行通道缺少"查询是否含具体对象"的前置检查。

## 五、改进方案（未实施，列入后续）

1. **放行通道增加对象性检查**：查询中无专有名词/菜品名/参数词时，不启用词汇放行
2. **阈值按题型动态化**：检测到疑问代词（it/this/that）且无具体名词时，强制走拒答分支
3. **表格内容结构化**（根治方案）：把换算表/营养表抽成 JSON 事实卡，从根上解决 reranker 对表格打低分的问题，届时词汇通道可整体下线

## 六、对答辩的意义

这道题的标准答法不是"我们加了混合召回所以更强"，而是：

> 我们做了 A/B 对比，发现混合召回对整体指标没有显著影响（+0.4pp / -0.7pp）。逐题拆解后发现它救了一道表格题、同时放行了一道模糊题，净效果为零。这说明**检索侧的改进必须配合拒答侧的约束**，否则收益会被副作用抵消——这也是我们下一阶段要做的对象性检查。

**用数据承认"这个改动没达到预期"，比声称"我们优化了 5%"更可信。**
