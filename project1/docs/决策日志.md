## 决策 1：UI 自动化迭代是否继续 → **停止**

**背景**：已做过 2 轮多模态视觉评价 + 修复（字号、间距、对齐）。

**当时的判断**：继续第 3 轮。

**推翻它的证据**：用 Playwright 读取 `getComputedStyle` 实测：

| 项目 | 实测值 | 视觉模型评价 |
|---|---|---|
| 1920 屏版心宽度 | **1040px** | "偏窄，建议收到 900–1000px"（比实测值还小） |
| h1 字号 | 23px | "标题层级不明显" |
| 正文字号 | 18px | "偏小" |

**结论**：视觉评价模型会自相矛盾，且天然倾向于"永远能挑出问题"。
改为**用计算样式做客观验证**，UI 迭代 2–3 轮后停止。真问题（投影 1920 宽下 760px 版心偏窄）通过 `@media (min-width:1600px)` 断点解决。

## 决策 2：扫描版教材 OCR → **否决**

**背景**：拿到《进化心理学（第二版）》PDF 做换书验证。

**直觉（用户提出）**："是不是有点剑走偏锋了？"

**实测确认**：

- 531 页，**纯扫描件，每页无文本层**（抽样文本长度全为 0）
- OCR 试跑 3 页：250 DPI 单页 7–10 秒 → 全书串行 **约 70 分钟**
- 质量抽查：出现"贞洁→贞浩/贞沾/贞洛""斟酌→贡酌"等错字

**否决理由**：
1. 错字会污染向量检索，让"换书验证"这个验证本身不可信——**为验证先把数据搞脏，本末倒置**
2. 换书验证的价值在"换了"，不在"换哪本"，任何有文本层的书都能证明同样结论
3. 外部 OCR API 需注册实名，不值得为一个验证环节开账号

**遗留**：该 PDF 留作远期"中文教材全栈切换"（TODO 方案C）的原料。

## 决策 3：先做查询翻译层，还是换中文书省掉它？ → **翻译层**

**背景**：TODO 方案 B 提出"中文提问对英文语料检索失效"的担忧，但未经验证。

### 第一轮实测（当时的错误结论）

| 中文问题 | 拒答 | top 分 | 初判 |
|---|---|---|---|
| 晚餐吃什么有助于长肌肉 | 是 | 0.293 | "假拒答，跨语言失效" |
| 汤匙和茶匙是不是同一个东西 | 是 | 0.001 | "跨语言彻底失效" |

**第一次结论**：中文提问 3/6 假拒答，翻车了。

### 第二次实测（自我推翻）

把同样问题**翻译成英文**再检索：

| 问题 | 英文译文检索 top | 结论 |
|---|---|---|
| 晚餐吃什么有助于长肌肉 | 0.127 | 译文也低 → **书里本来就没有** |
| 汤匙和茶匙是不是同一个东西 | 0.013 | 同上 |
| 增肌期一天该吃多少克蛋白质 | 0.054 | 同上 |

**第一次结论被推翻**：那 3 个是**真拒答（答对了）**，不是跨语言问题。

### 第三轮实测（真正的对照实验）

用评测集中**已知书里有答案**的 in_scope 题做中英对照：

| 提问语言 | in_scope 假拒答率 |
|---|---|
| 英文基线（30 题） | **1 题 / 3%** |
| 中文手译（12 题） | **3 题 / 25%** |

**关键发现——失败方式很隐蔽**：

- `i03` 怎么做高蛋白千层面 → top=**0.457**（已过阈值）→ 检索到的却是错的段落 → 模型自己输出拒答
- `i04` 蛋白牛油果吐司需要哪些食材 → top=**0.674**（远超线）→ 同样答不出
- 这两题的**英文版都答对了**

即：问题不在阈值，在**跨语言向量的排序噪声**——分数漂亮，内容不对。

### 成本对比（决策依据）

| | 方案B 查询翻译层 | 换中文 EPUB |
|---|---|---|
| 工作量 | rag.py 加一个函数 | 写解析器 + 建库 + 新题集 + 重跑 50 题 + 重做 A/B + 重校准阈值 |
| 数据 | **一个数不动** | 50 题评测、A/B 实验全部作废 |
| 中文语料效果 | 无需验证 | **未知，需从零校准** |
| 中文评测标准答案 | 无需设计 | TODO 方案C 自评："心理学概念评测标准答案更难设计" |

**决策：先做翻译层，换书排在其验证通过之后**（先让系统本身过关，再换变量，否则出问题无法归因）。

## 决策 4："这是业界做法吗？" → **查证后表述为"业界主流范式之一"**

用户主动提出未查证的说法不敢在答辩用。检索确认 4 条依据：

1. **三种跨语言 RAG 范式**（LumeValley, 2026-08）：Translate-Query-Retrieve / Translate-Document / Cross-Lingual Embedding——查询翻译是其一，优点是"实现简单、只需维护单语种知识库"
2. **学术界与工业界一般采用 Query 翻译**（相比文档翻译：不占存储、无需线下预处理）
3. **中文工程实测**（CSDN, 2026）：仅多语言 embedding 时 evidence hit rate 71%，**叠加 translation pivot 后 80%**，P95 时延仅 +11%
4. 百度 QAnything 产品化的 **TRT（Translate-Retrieve-Translate）** 流程

**措辞修正**：业界"前沿"是跨语言嵌入直连；我们用的"多语 embedding + 翻译枢纽"是**主流成熟路线**。答辩表述为"业界三种主流范式之一"，避免被反问戳穿。

## 决策 5：实现与验证

### 实现（rag.py · 查询翻译层）

- 检测 CJK → 调 LLM 译为英文检索式 → **英文走完整 dense + lexical + rerank**
- 生成阶段仍用**原始中文问题**（回答语言、页码引用规则不受影响）
- 进程内缓存（重复提问不重复调模型）
- **三级降级**：翻译失败 / 超时 / 译文仍含中文 → 退回原句检索，最坏情况等价于没有本层

### 验证结果

**① 中文 12 题对照（核心指标）**

| | 翻译层前 | 翻译层后 |
|---|---|---|
| 拒答数 | 3/12（25%） | **0/12（0%）** |
| i03 / i04（隐蔽失败题） | 拒答 | **双双转为能答** |
| i07 | 拒答（0.164） | 能答（0.615） |
| top 分区间 | 0.16–0.99 | 0.53–0.999 |

翻译质量抽查：`高蛋白法式吐司→protein French toast`、`鸡肉沙爹串→chicken satay skewers`、`度→degrees F`，术语准确。

**② 英文全量 50 题回归（防回退）**

出现指标下降（96%→92%），随即归因，**不归因于翻译层**：

- 评测集中文题 **0 个** → 翻译层触发 **0 次**（`if not _CJK_RE.search(query)` 直通）
- 检索分数漂移 >0.15 的题：**0 题**（检索层 100% 稳定）
- 唯一状态翻转题 `v05 "Is it healthy?"`：top 分 **0.158→0.158 完全相同**，翻转发生在生成阶段

**③ 附带发现：系统存在 ±4pp 生成方差**

同配置连续 3 次全量评测：96% / 92% / 94%（课外拒答率 95% / 85% / 90%）。
根因：temperature=0.3 下 LLM 对边界题（vague 类）的拒答判断非确定性。
**答辩用法**：主动披露评测方差，比报一个漂亮但不可复现的数字更可信；也说明评测结论应看趋势而非单次波动。

## 方法论沉淀

1. **用数据推翻直觉，也用数据保护结论**——本晚两次自我推翻（OCR 否决、"中文失效"误判）都靠对照实验，不靠辩论
2. **多模态视觉评价不可尽信**，客观量测（计算样式、分数）优先
3. **验证要控制变量**：翻译层验证先保证"英文路径零触发"，再谈中文收益
4. **归因比结论重要**：指标下降 ≠ 回退，先查触发次数、分数漂移、翻转位置，再下判断
