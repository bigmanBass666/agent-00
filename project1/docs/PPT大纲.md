## 第 2 页｜我们要解决什么问题
- 大模型的通病：会编（幻觉），因为它记的是语言统计，不是教材
- 目标：让它只基于一本教材回答，每个事实都能翻回原书页码
- 三条硬线：只查教材、必须给页码、不覆盖就说"未找到"
- 教材：The Anabolic Cookbook 2.0（205 页，209 条书签，142 章节）
- 为什么选它：结构比一般教材更清晰（一菜一章），且与参考案例（计算机网络）完全差异化

## 第 3 页｜技术选型：为什么不走参考路径
| 方案 | 组成 | 我们的判断 |
|---|---|---|
| A 参考路径 | DSH + SQLite FTS5 + BM25 | 与参考案例重复，且关键词匹配对口语化提问不敏感 |
| B | ChromaDB/FAISS + LangChain | 数据仅 159 块，框架抽象成本大于收益 |
| **C（我们的选择，变体）** | 自研检索 + 直接调 LLM API | 链路短、每层可打印中间结果、便于归因 |
| D | 低代码平台 | 无法体现技术深度 |
- 差异化：教材不同、检索方式不同（向量+词汇混合）、**未使用方案 A**
- 归类说明：C 的变体（知识库用 json+npy 而非 SQLite，检索用 numpy 余弦 + 交叉编码器重排）
- 报备说明：文档要求自定义方案需教师确认，我们已准备归类材料（若需补报可当场说明）

## 第 4 页｜系统架构（一页看懂全链路）
```
问题 → [中文?] 查询翻译 → 英文检索式（缓存 + 三级降级回原句）
      → 双路召回（向量 top-20 + IDF词汇 top-20）
      → 合并去重（≤40）→ reranker 精排 top-3
      → 第一层拒答（阈值0.3 且 词汇分<0.85）
      → Prompt 组装（3 块完整文本 + 页码/章节/相关度）
      → Qwen3-8B 生成（用原始问题，回答语言不变）
      → 第二层拒答（LLM 判定资料不足）
      → 回答 + 【教材 p.XX】
      → 拒答分支 → 自动生成工单 → 人工工作台 /handoff
```
- 一句话：**翻译在前、检索两路、拒答两层、答不上转人工，每层都能单独验证**

## 第 5 页｜Phase 1 知识库构建
- PDF 205 页 → 193 页有文字
- **按书签章节切块**（不是按字数无脑切）：菜谱书"一菜一章"，配料和步骤不能分家
- 章内超 3500 字符才二次切分，保留 300 字符重叠
- 结果：**159 块 / 142 章节**，87% 章节恰好一块
- 每块四字段：text / page_start / page_end / chapter
- 校验：块数与向量数一致、页码元数据完整、**自检索 3/3 命中**
- **回应"800~1200 tokens"要求**：实测合并到 864 tokens 后，准确率 78.6%（章节切 89.7%）、页码定位 85.7%（93.1%）→ 按文档"等效粒度"保留章节切（一菜一章的天然单元即 475 tokens）

## 第 6 页｜Phase 2 检索工具 knowledge_search
- 函数：`knowledge_search(query, top_k)` → 返回 `{text, page_start, page_end, chapter, score, citation}`
- 双路召回为什么必要：
  - 向量擅长"意思相近"，但对**表格碎片**几乎失灵（实测换算表 reranker 只给 0.17）
  - 词汇召回用 IDF 加权，罕见词（satay、tablespoons）命中即强信号
- 精排用 cross-encoder，把 40 个候选压到 3 个再喂 LLM

## 第 7 页｜Phase 2 系统提示词（R1~R6 怎么落地）
| 约束 | 实现位置 |
|---|---|
| R1 先检索 | 代码顺序强制：`retrieve()` 一定在 `llm_call()` 之前 |
| R2 只用教材 | 提示词第 1 条 + 资料隔离（不传任何外部知识） |
| R3 页码引用 | 分块带页码 + 提示词规定格式 + 正则自动核验 |
| R4 中文+术语 | 提示词第 4 条（禁中英拼接） |
| R5 如实拒答 | **三档拒答**：完全无关 / 部分相关 / 过宽 |
| R6 不抄原文 | 提示词第 5 条 + 最长公共子串自动检测 |
- 亮点：拒答不是"没找到就说不知道"，而是分清三种情况

## 第 8 页｜拒答机制：为什么必须两层
- 第一层（阈值）：拦完全无关，实测分数 0.001~0.06，省钱且零幻觉风险
- 第二层（LLM）：拦"看着相关但书里没有"的诱导题
- **实证**：`Which protein powder brand should I buy?` 检索分 **0.579 > 阈值**，阈值层拦不住，靠 LLM 层拒答
- 反向通道：词汇分 ≥0.85 时绕过阈值，救表格类课内题
- 结论：单靠阈值会漏，单靠 LLM 会飘

## 第 9 页｜测试方法（对齐课程脚手架）
- 评测集 **50 条**：课内 30 / 课外 10 / 诱导 5 / 模糊 5（60/20/10/10，全部达标）
- 每题带 gold_pages + 中英双语 gold_keywords
- 逐条判定五类：correct / wrong / hallucinated / refuse_correct / refuse_wrong
- 另设 **5 条 holdout**（含 1 条库外陷阱题）供现场抽问，不参与调优
- 自动检测 R6：回答与资料的 ≥150 字连续公共子串

## 第 12 页｜失败案例 1：模型偷偷换了食材
- 题：`How to make Swedish meatballs?`
- 原文：`ground turkey`（火鸡）
- 系统答："鸡胸肉或牛肉末"
- 根因：菜谱常识压过教材原文（R2 隐蔽违规）
- 为什么难发现：页码对、数字对，只有实体错
- 改进：生成后抽取食材做集合比对，不一致打回

## 第 13 页｜失败案例 2：表格被压平 → 已修复
- 题：`How many tablespoons are in one cup?`
- 现象：系统答 **16 tbsp**，正确是 **8 tbsp**（差一倍）
- 根因：PDF 两列表被提取成一行连续文本 `3 tsp 1 tbsp 8 tbsp 1 cup 16 oz 1 lb`，`16 oz` 错配给了 `tbsp`
- 修复：`page.find_tables()` 抽表 → 转成结构化句子 `8 tbsp = 1 cup` 单独成块；过滤掉"准备时间/难度"噪音表，只留 21 个真数据表
- 结果：现在稳定回答"1 杯等于 8 汤匙【教材 p.14】"，页码定位 93.1% → 96.6%

## 第 17 页｜查询翻译层：中文提问失效的发现与修复（本轮新增）
- **发现问题**：英文知识库 + 中文提问，课内题假拒答率 **25%**（英文基线 3%）
- **失败很隐蔽**：`i03 怎么做高蛋白千层面` top=**0.457 已过阈值**，但跨语言向量排序噪声导致检索到错的段落 → 模型只能拒答（英文版该题答对）
- **业界依据**：跨语言 RAG 三种主流范式之一 Translate-Query-Retrieve（另有文档翻译、跨语言嵌入直连）；中文工程实测：仅多语言 embedding 命中 71% → 叠加 translation pivot 后 80%，P95 时延仅 +11%
- **实现**：CJK 检测 → LLM 译成英文检索式 → 进程内缓存 → **三级降级**（失败/超时/仍含中文都回原句，最坏等价于没有本层）
- **关键设计**：检索用译文（dense + 词汇 + rerank 都吃到英文红利），**生成仍用原始中文问题**（回答语言、页码引用规则零影响）
- **验证**：中文 12 题拒答 **3→0**（i03/i04/i07 全部救回），top 分 0.16→0.53 起步；英文 50 题回归**触发 0 次**（评测集无中文题，代码级直通），检索漂移 0 题
- 我们的架构演进：embedding 本就是多语种 bge-m3（业界"跨语言嵌入"路线），**实测不够用 → 叠加"翻译枢纽"路线**，两条路线的取舍有数据支撑

## 第 18 页｜转人工机制：把课程要求做成闭环（本轮新增）
- **课程原话**："回答都要基于我给你的基本资料，找不到就不要回答……进一步的做的话呢，就是让它**自动转向人工**，人工在边上休息，AI 抛一个它回答不了的问题过来的时候，你才开始工作"
- **实现**：
  - 拒答 → 自动生成工单（`webui/tickets.jsonl`），响应携带工单号/建单时间
  - 问答页拒答卡片显示：`✓ 已自动转人工 · 工单 T20261019-001 · 人工已在 /handoff 接单`
  - `/handoff` 人工工作台：待处理/已处理/累计统计、接单按钮、10 秒自动刷新
- **双端闭环**：AI 答不上 → 自动落单 → 人接单 → 标记处理
- 与两层拒答机制衔接：阈值层/LLM 层拒答的题都会落单，**人工端看到的就是系统最没把握的问题**
