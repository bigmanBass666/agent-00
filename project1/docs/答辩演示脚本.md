## 三、演示（4 分钟，3 道题）

### 题 1：课内题（展示正常能力）
```
What temperature and how long should I bake egg white bites?
```
预期输出：`你应该将烤箱预热至 400°F/204°C，并将蛋清杯烘烤 10 分钟或直到完全熟透【教材 p.27】。`

**讲解词**："注意这里，它不只是给了答案，还标了 p.27。我们可以现场翻到第 27 页核对——这就是 R3 页码引用。"

### 题 2：课外题（展示拒答）
```
What is the capital of France?
```
预期输出：`根据教材内容未找到相关信息。`

**讲解词**："检索分只有 0.009，第一层阈值直接拦掉了，大模型根本没被调用。所以它连'巴黎'这个词都不会说出来——**零幻觉风险**。"

### 题 3：陷阱题（最出彩，从 holdout 现场抽）
```
How do I make sushi rolls at home?
```
预期输出：拒答。

**讲解词**："这题是我特意准备的。寿司在书里完全没出现过，但'怎么做'这个句式和书里所有菜谱高度相似。系统检索分 0.025，正确拒答。"

### 备选：高风险诱导题（如果时间够）
```
Which protein powder brand should I buy?
```
预期输出：拒答。

**讲解词（这段一定要讲，是全组最亮的点）**：
> "这题比较阴险。书里确实提到 protein powder，所以检索分到了 **0.579，高于我们的阈值 0.3**，第一层拦不住。但第二层 LLM 读完资料后判断'没有品牌推荐'，正确拒答了。
>
> **这就是为什么我们要做两层拒答**：单靠阈值会漏，单靠大模型会飘。"

### 备选演示：多语言双库自动切换（时间够就展示）

**操作**：知识库下拉保持"自动（按语言切换）"

1. 输入中文：`桑代克的拼图盒实验用的是什么动物？`
   → 答案卡片顶部显示 `知识库 《原子习惯》（中文教材） route:auto:zh`，答出"猫【教材 p.45】"（top 0.982）
2. 输入英文：`How many tablespoons are in one cup?`
   → 显示 `知识库 The Anabolic Cookbook 2.0 route:auto:en`，答"1 杯 = 8 汤匙【教材 p.14】"

**讲解词**：
> "注意答案上方的路由标签。我们知识库里**同时放着两本书**——一本英文食谱、一本中文方法论，提问是什么语言就自动切到对应的库，不用人工选。
>
> 这就是拓展清单第一项：'多语言支持：知识库同时包含中英文教材，检索时自动切换'。
>
> （想展示查询翻译层的话）把下拉切到 'Cookbook · 英文' 再用中文问——它会先翻译成英文去查英文书，这是跨语言检索的业界主流做法之一。"

## 四、数据（3 分钟）

### 4.1 亮指标（30 秒）

| 指标 | 数值 | 线 |
|---|---|---|
| 准确率 | 89.7% | ≥70% |
| 拒答正确率 | 85.7% | ≥70% |
| 页码引用覆盖率 | 100% | — |
| 幻觉 | 2 条 | <3 |

**讲解词**："评测集 50 条，严格按课程脚手架的配比：课内 30、课外 10、诱导 5、模糊 5，正好 60/20/10/10。另外留了 5 条 holdout，刚才那道寿司题就是从里面抽的，不参与调优。"

### 4.2 三轮迭代（1 分钟）

| 轮次 | 改动 | 拒答正确率 |
|---|---|---|
| R1 | 基线 | 87.5% |
| R2 | 加混合召回 + 重写提示词 | **87.5%（零提升）** |
| R3 | 修一个 bug | **93.8%** |

**讲解词（这是最能体现"真做过"的一段）**：
> "第二轮我们加了一整套混合召回，指标一点没动。当时很困惑，后来把实际喂给大模型的 context 打印出来才发现——组装资料时写了 `text[:2000]`，而全书 38% 的块超过 2000 字，**答案被截掉了半截**。检索是对的，模型看不到。
>
> 修完这个 bug，指标才动。这件事教给我们一句话：**指标不动的时候，先查数据管道，别急着换算法。**"

### 4.3 失败案例（1.5 分钟，选最有意思的讲）

**i08 瑞典肉丸——模型偷偷换了食材**
> "原文写的是 ground turkey（火鸡肉），系统答成了'鸡胸肉或牛肉末'。页码是对的、步骤是对的，只有食材被替换了。
>
> 为什么会这样？因为瑞典肉丸的常识做法就是牛肉猪肉，模型的世界知识压过了教材原文。这是 R2'禁止使用内部知识'最隐蔽的一种违规——它不编数字，它换实体。
>
> 这也说明一个问题：**光靠提示词写'不要用内部知识'是不够的**，得在生成后做实体比对。"

## 五、技术要点（2 分钟，挑两个讲）

### 讲点 1：为什么按章节切，不按字数切
> "菜谱书是'一道菜一个章节'。如果按固定 500 字切，很可能配料在一块、步骤在另一块，回答必然残缺。所以我们优先按书签章节切，159 块覆盖 142 个章节，87% 的章节正好一块。"

### 讲点 2：混合召回的对比实验（加分项）
> "我们做了 A/B：混合召回 89.7%，纯向量 89.3%，**基本持平**。
>
> 逐题拆开看才发现原因：混合召回救了一道表格题（一 cup 多少 tbsp，纯向量会误拒），但同时放行了一道模糊题（Is it healthy?，词汇分满分绕过了阈值）。**一救一伤，正好抵消。**
>
> 所以这个实验的真正价值不是证明我们优化了，而是定位到一个设计缺陷：词汇放行通道缺少'问题是否有明确对象'的检查。这个已经写进改进清单了。"

## 六、可能被问到的问题（提前准备）

### Q1：为什么不用老师给的参考方案 A（DSH + FTS5）？
> "两个原因。一是课程鼓励技术栈差异化，非方案 A 实现完整可以拿满技术多样性分；二是菜谱书的提问都是口语化的（'how do I make…'），FTS5 的关键词匹配对同义表达不敏感，向量检索更合适。我们的实现属于方案 C 的变体——直接调 API + 自研检索，没引框架，因为数据只有 159 块，框架的抽象成本大于收益。"

### Q2：你的知识库和问话模型是同源的吗？
> "老师您说的同源，我们理解是**建库和查询必须用同一个 embedding 模型**，否则向量空间对不上。我们两边都是 bge-m3，这一点是满足的。生成用的是 Qwen3-8B，跟 embedding 不是同一个模型——这是标准 RAG 架构，生成模型不参与向量计算，所以不影响匹配。"

### Q3：R1 说'先检索再回答'，你怎么证明？
> "代码层面强制：`ask()` 里顺序是 `retrieve()` → 阈值判断 → `llm_call()`，大模型调用写在检索之后，没有分支能绕过。日志里每次回答前都会打印检索分数。而且阈值层拒答的时候，大模型根本不会被调用——这本身就是证据。"

### Q4：R6 说不许抄原文，你怎么验证？
> "写了个自动检测：把回答和检索到的原文去空白后算最长连续公共子串，超过 150 字就标记为疑似抄原文。50 题里 0 条违规。"

### Q5：2 条幻觉为什么没修？
> "修了方案但没时间实施。根因是模型用世界知识替换实体，靠提示词堵不住，得在生成后抽食材做集合比对。这是我们写进'如果再做一次'的第一条。"

### Q6：教材为什么不用在学的课程？
> "组内能拿到的课程电子版教材有限，老师给的计算机网络在学习通上没找到。我们选这本书是因为它 205 页、209 条书签、142 个章节，章节结构比一般教材更清晰，正好能把'按章节分块'这个要求验证透。而且系统跟教材是解耦的——换书只改配置里一行路径，重跑三个脚本就行，不用动任何检索和拒答逻辑。"

### Q7：中文能问吗？
> "能问，而且做法类问题几乎无损——中文问'怎么做蛋白法式吐司'检索分 0.996，和英文一样。
>
> 早期数值类确实会失效（'一杯多少汤匙'这类），因为中文词匹配不上英文表格文本。**现已加查询翻译层修复**：中文问题先译成英文检索式再去检索，生成时仍用原始中文问题、中文回答。实测中文 12 道课内题的假拒答从 3 条降到 **0 条**，英文路径零触发。这是跨语言 RAG 的业界主流做法之一（Translate-Query-Retrieve）。"

### Q8（`materials/15` 学完自测 1）：RAG 五步流程是什么？哪一步出错最可能导致"引用错误资料"？
> "五步是：**索引（建库分块）→ 检索 → 增强（组装上下文）→ 生成 → 评估**。
>
> 最容易导致'引用错误资料'的是**检索 + 增强**这两步。我们自己就踩过第二个坑：检索完全正确、reranker 把正确块排第一，但组装 context 时写了 `text[:2000]` 把答案截掉了半截，模型只能瞎猜——**看起来是生成错了，其实证据在增强这一步丢了**。所以我们的改进清单第一条就是'打印最终 prompt 做常规动作'。"

### Q9（学完自测 2）：为什么相似度阈值要放在调用 LLM 之前？放在之后行不行？
> "放之前有两个理由：**省钱**和**防幻觉**。实测课外题的检索分是 0.001~0.06，根本不该进大模型——拦在阈值层，模型一次都不被调用，零幻觉风险、零 token 成本。
>
> 放之后不行：模型已经读了资料、生成了答案，这时候才发现'分数太低'，**该编的已经编完了**，而且 token 白花了。我们代码里 `ask()` 的顺序是 `retrieve()` → 阈值判断 → `llm_call()`，阈值拒答时 LLM 调用根本不会执行。"

### Q10（学完自测 3）：分块大小与检索精度是什么关系？你的语料上为什么选当前值？
> "块太小，答案被切碎（配料在一块、步骤在另一块）；块太大，多个主题混进一块，精排打分被稀释，模型还会串味。
>
> 我们做了 A/B：章节切平均 475 tokens，准确率 89.7%；硬合并到 864 tokens，准确率掉到 78.6%、页码定位 93.1%→85.7%。所以选章节切——菜谱'一菜一章'是天然语义单元，正符合文档说的'**800~1200 tokens 或等效粒度**'。"

### Q11（【必看】Lewis 2020 RAG 论文）：为什么"检索"能增强生成？
> "大模型的参数化记忆是压缩过的：易过时、易编造、无法溯源。检索库是非参数化记忆：可更新、可查证、有出处。
>
> RAG 把'查证'外包给检索器，生成器只负责组织语言——这样既减少幻觉，又让每个结论能指回原始文档。我们项目就是这个思路的极端版：**只认一本教材，每个事实给页码，查不到就说不知道**。"

### Q12：拓展项里的"多语言支持：检索时自动切换"是怎么实现的？
> "两本书各自建库——英文 Cookbook 180 块、中文《原子习惯》58 块，向量互不干扰。
>
> WebUI 在请求级做路由：提问含中文就查中文库、否则查英文库，**不需要人工选**；每本书带语言标签，中文库对中文问题原生检索（不翻译），英文库对中文问题才启用查询翻译层——同一个翻译函数按目标库语言开关。
>
> 4 项路由测试全过（auto:zh / auto:en / manual:en / api/info），答案卡片会显示命中的知识库和路由方式，可现场演示。"

### Q13：课堂上说的"自动转人工"，你们做了吗？
> "做了。拒答的那一刻系统自动生成工单（工单号、问题、时间），问答页显示'已自动转人工 · 工单 XXX'；另有一个 `/handoff` 人工工作台，显示待处理/已处理统计，人工点'开始处理'完成闭环。
>
> 它和两层拒答是**同一套判定的两个出口**：系统最没把握的问题，正是人工最该看到的问题——AI 答不了，人在边上休息；AI 抛一个问题过来，人才开始工作。这是按 10 月 12 日课上讲的模式实现的。"
