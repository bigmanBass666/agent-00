# 对比实验：分块粒度（章节切 vs 合并切）

> 对应评分项：知识库质量 → **分块合理性（8 分）**
> 实验日期：2026-10-18
> 同一教材、同一评测集（50 题）、同一模型与提示词，仅改变分块参数

## 一、问题背景

作业文档 Phase 1 要求："按章节进行语义分块（**每块 800~1200 tokens 或等效粒度**，块间有重叠）"。

我们的初始方案是**按 PDF 书签章节切块**，实测平均 475 字符/tokens 等效值低于 800。为了判断这是缺陷还是合理取舍，做了本实验。

## 二、实验设计

| 组别 | 策略 | 块数 | 平均块长 | 章节覆盖 |
|------|------|------|---------|---------|
| **A（当前方案）** | 章节优先：书签章节变化即切块 | 159 | 1900 字符 ≈ **475 tokens** | 142 章节 |
| **B（对照组）** | 合并切：跨章节累积到 3200 字符（≈800 tokens）再切 | 93 | 3458 字符 ≈ **864 tokens** | 12 章节 |

**控制变量**：同一 PDF、同一 bge-m3 向量化、同一 reranker、同一 Prompt、同一阈值、同一 50 题评测集与判定规则。

**复现命令**：

```bash
# A 组（默认）
python build_kb.py && python run_eval_v2.py --fresh && python judge_results.py

# B 组
CHUNK_TARGET_MIN=3200 python build_kb.py && python run_eval_v2.py --fresh && python judge_results.py
```

## 三、结果

| 指标 | A：章节切（475 tokens） | B：合并切（864 tokens） | 差值 |
|------|----------------------|----------------------|------|
| **准确率** | **89.7%**（26/29） | 78.6%（22/28） | **-11.1pp** |
| **拒答正确率** | **85.7%**（18/21） | 77.3%（17/22） | **-8.4pp** |
| 页码引用覆盖率 | 100%（29/29） | 100%（28/28） | 持平 |
| **页码定位准确率** | **93.1%**（27/29） | 85.7%（24/28） | **-7.4pp** |
| 标准要素全覆盖率 | **79.3%**（23/29） | 71.4%（20/28） | **-7.9pp** |
| 判定分布 | correct 26 / wrong 1 / hallucinated 2 / refuse_wrong 3 | correct 22 / wrong 4 / hallucinated 2 / refuse_wrong 5 | — |

**B 组在所有维度全面下降，其中“页码定位”和“要素覆盖”跌幅最大。**

## 四、原因分析

### 4.1 合并块把多道菜塞进了一个检索单元
B 组为了凑够 800 tokens，必须把 2~3 个章节（多道菜谱）合并成一块。当用户问"瑞典肉丸怎么做"时，检索返回的块里同时有肉丸、炖菜、烤鸡的做法，模型容易：
- 把 A 菜的用量套到 B 菜上
- 页码标注指向块的起始页，与真实内容错位（页码定位准确率从 93.1% 掉到 85.7%）

### 4.2 wrong 从 1 条涨到 4 条
合并后模型需要在一段混杂文本中"挑出"对应菜品，错配概率显著上升。

### 4.3 章节元数据失真
B 组因为跨章节合并，每块只能记录起始章节，导致"章节覆盖"从 142 降到 12——这会直接影响评分项"章节覆盖率（4 分）"，也让回答末尾的"来源章节"提示失去意义。

## 五、结论与决策

**决策：保留 A 方案（章节切），并以"等效粒度"作为合规依据。**

理由：

1. **语义完整性优先于 token 数达标**。菜谱书"一道菜 = 一个章节"是作者设定的语义边界，475 tokens 恰好是该语义单元的天然体量。强行合并到 800 tokens 会破坏这个边界。
2. **数据支持**：准确率 -11.1pp、页码定位 -7.4pp，代价远大于"token 数看起来达标"的收益。
3. **作业文档原文允许**："每块 800~1200 tokens **或等效粒度**"——"等效粒度"即指按语义单元切分后的自然块大小。
4. **R3 页码引用要求**：页码定位准确率是本项目的核心指标（93.1% vs 85.7%），章节切在这一点上明显更优。

## 六、答辩话术

> "老师要求每块 800~1200 tokens 或等效粒度。我们实测了两种切法：按 800 tokens 合并切，准确率 78.6%；按章节切（平均 475 tokens），准确率 89.7%，页码定位还高出 7 个百分点。
>
> 原因是菜谱书一道菜就是一个章节，475 tokens 正好是一个语义单元的天然体量。合并到 800 就必须把两三道菜塞进一块，模型会串味、页码也会错位。
>
> 所以我们选了章节切，依据是文档里说的'**等效粒度**'。这个对比实验的数据在 `docs/对比实验_分块粒度.md`。"
