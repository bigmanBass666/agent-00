# 系统提示词设计说明

> 对应交付物 3：系统提示词（文本文件 + 设计说明）
> 提示词文件：`prompt/system_prompt.txt`
> 加载方式：`rag.py` 启动时读取该文件；文件缺失时使用内置兜底副本

## 一、提示词全文

```
你是基于《The Anabolic Cookbook 2.0》回答问题的助手。严格遵守以下规则：
1. 只能使用【资料】提供的内容作为事实依据，绝对禁止使用内部知识补充数字、用量、步骤或结论。
2. 拒答判定分三种情况：
   a) 【资料】与问题完全无关 → 只输出：根据教材内容未找到相关信息。
   b) 【资料】只有部分相关内容 → 基于相关部分回答，并明确指出资料中未覆盖的部分，不得用常识补全。
   c) 问题没有指明具体菜品、食谱或参数，无法确定回答哪一条（如"怎么做菜""该吃什么"）→ 只输出：问题过于宽泛，请指明具体食谱或菜品。
3. 每个事实性陈述后标注页码，格式【教材 p.XX】；跨页用【教材 p.XX-YY】。
4. 用简洁中文回答，专业术语可在括号中保留英文原词（如 乳清蛋白(whey)），禁止中英拼接造词。
5. 以转述为主：不得连续照抄资料原文超过 2 句，不得整段罗列原步骤，应概括要点。
6. 必须紧扣提问中的具体对象作答，不得自行挑选一个菜谱代答；回答末尾用一句话点明来源章节。
```

## 二、逐条设计理由

| 规则 | 对应约束 | 设计理由 | 不这样写会怎样 |
|------|---------|---------|---------------|
| 1 | R2 | 明确"事实依据"仅限于【资料】，并列举报纸型、数字、步骤、结论四类最容易被模型"补全"的内容 | 模型会用世界知识补齐配料（实测：原文 ground turkey 被写成"鸡肉或牛肉"） |
| 2 | R5 | **三档拒答**是本提示词的核心设计：完全无关 / 部分相关 / 过于宽泛，三种情况的正确行为完全不同 | 一刀切"没找到就拒答"会把"部分相关"的 FAQ 类问题误拒（实测 i13 检索分 0.98 却拒答） |
| 2c | R5 | 单独规定"问题无具体对象"时的行为，要求反问而不是自选一个菜谱 | 模型会挑一道菜代答（实测 v01"怎么做菜"被答成"土豆做法"） |
| 3 | R3 | 规定页码格式与跨页写法，使输出可被正则解析、可自动核验 | 模型会写"第 27 页""p27"等多种写法，无法自动统计溯源率 |
| 4 | R4 | 规定"术语可保留英文但须放在括号内"，禁止中英拼接 | 出现"一份水melon（西瓜）"这类病句 |
| 5 | R6 | 版权保护要求，量化到"连续 2 句"，并要求"概括要点"而非罗列步骤 | 整段照抄菜谱步骤（实测首轮 lasagna 违规） |
| 6 | R2/R5 | 兜底规则，防止模型"替用户选对象"或答非所问 | 与 2c 同源问题 |

## 三、资料注入格式

```
【教材p.27｜章节：Egg White Bites｜相关度=0.9430】
<该块的完整文本，不截断>
```

设计要点：
1. **页码前置**：让模型在生成时能直接引用，不必自己推断
2. **章节名**：帮助模型判断该块是否真的对题（Prompt 规则 6 要求末尾点明来源章节）
3. **相关度**：给模型一个"可信度"信号，低相关时应更保守
4. **不截断**：早期版本用 `text[:2000]` 截断，导致 38% 长块的关键内容对模型不可见——这是本项目最大的一个 bug，修复后拒答正确率从 87.5% 提升到 93.8%

## 四、版本演进

| 版本 | 关键改动 | 效果 |
|------|---------|------|
| v1 | "资料中没有相关信息时拒答"（一刀切） | FAQ 类部分相关问题被误拒 |
| v2 | 改为三档拒答 + 模糊问题反问 + 禁中英拼接 | 模糊题 v01 从误答变为正确拒答 |
| v3（当前） | 增加"不得自行挑选菜谱代答"；资料块改为完整注入 | 页码引用率 100%；拒答正确率 87.5% → 93.8% |

## 五、参数设置

| 参数 | 值 | 理由 |
|------|-----|------|
| temperature | 0.3 | 事实型问答需要稳定输出，但不能为 0（避免重复卡死） |
| enable_thinking | False | 关闭推理模式，减少"自由发挥"空间，严格执行拒答约束 |
| max_tokens | 1024 | 菜谱类回答一般 300-600 字，1024 足够且可控成本 |
