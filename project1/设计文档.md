## 〇、教材选择说明（先讲清楚，避免评审第一眼产生疑问）

### 选用教材
**The Anabolic Cookbook 2.0（Greg Doucette）**，205 页，PDF 书签 209 条，可解析章节 142 个。

### 为什么选它
1. **满足作业文档的全部硬性技术条件**：PDF ≥100 页 ✅、含清晰章节结构 ✅（209 条书签）、可提取文字 ✅（193/205 页有文字）。
2. **章节结构质量优于多数教材**：菜谱书"一道菜 = 一个章节"，142 个章节粒度均匀，天然适合验证"按章节语义分块"这一 Phase 1 核心要求。用这本书反而能把分块策略的取舍讲得更清楚（见第二节）。
3. **与参考案例完全差异化**：v2 要求"需选择不同的课程教材"，且"鼓励采用与参考案例不同的技术栈"。本书与《计算机网络》无任何重叠。

### 需要坦诚说明的一点
作业文档的口头补充中提到"最好是限定在你在学的那些课程里挑一本"。组内实际可获取的课程电子版教材有限（老师提供的《计算机网络》在学习通上未能定位），因此在可获取的 PDF 中选择了结构质量最好的一本，并按"课程知识库"的同等标准完成全部要求（R1~R6、Phase 1/2、7 项交付物）。

### 这一点不影响系统有效性
本系统的管线**与教材完全解耦**：换教材只需改 `config.py` 中的 `PDF_PATH`，重跑 `build_kb.py → validate_kb.py → run_eval_v2.py` 即可，无需修改任何检索、提示词或拒答逻辑。完整换书流程见 README「换教材流程」一节。

## 〇之二、技术栈归类与选择理由

### 归类：方案 C 的变体（自定义组合）

作业文档第五节给了 A/B/C/D 四个方案，并允许"自定义方案：可组合上述方案的组件……需经教师确认"。

本项目的实际组合是：

| 环节 | 本项目的选择 | 对应方案特征 |
|------|-------------|-------------|
| 智能体 | **不引入框架，直接调用 LLM API** | 方案 C |
| 知识库 | `kb_chunks.json` + `kb_vectors.npy`（非 SQLite） | 自定义 |
| 检索 | **向量余弦 + IDF 词汇召回**（非 FTS5 全文检索） | 方案 B 的检索思想 |
| 精排 | bge-reranker-v2-m3 交叉编码器 | 自定义（超出四个方案） |

**即：保留方案 C"直接调 API、轻量自研"的骨架，把 FTS5 全文检索替换为向量检索 + 交叉编码器重排。**

### 为什么不直接用参考方案 A（DSH + FTS5）

1. **差异化要求**：v2 明确"选择非参考路径（非方案 A）且实现完整者，该单项可获满分"，并鼓励各组错开技术栈。参考案例是 A，我们若用 C 变体正好错开。
2. **检索质量适配语料**：菜谱书的提问高度口语化（"how do I make…""what's in…"），FTS5 的关键词精确匹配对同义表达不敏感；向量检索能覆盖语义相近表述。
3. **规模决定的工程取舍**：全书仅 159 块。这个量级下，FAISS/Chroma 的索引优势不存在（numpy 暴力余弦为毫秒级），引入框架的抽象成本大于收益。
4. **可归因性**：自研管线的每一层（向量分、rerank 分、词汇分、最终 context）都能打印。本项目三轮迭代中定位到的 `text[:2000]` 截断 bug，正是靠"能把中间态打出来"才发现的。

### 关于"需经教师确认"

本项目未在开工前单独报备自定义方案。若评审认为需要补报，可按本节归类说明提交：**方案 C + 向量检索替代 FTS5 + 增加交叉编码器精排**，未引入任何第三方 RAG 框架。

## 一、系统架构

```
用户提问
   │
   ▼
┌─────────────────────────────────────────────────────┐
│ 混合召回（并行两路）                                  │
│  ① bge-m3 embedding 余弦相似度 top-20                │
│  ② IDF 加权词汇召回 top-20（救表格/短事实类查询）      │
│     → 合并去重，最多 40 个候选                        │
├─────────────────────────────────────────────────────┤
│ bge-reranker-v2-m3 交叉编码器精排 → top-3            │
├─────────────────────────────────────────────────────┤
│ 【第一层拒答】reranker 最高分 < 0.3                   │
│                且 词汇分 < 0.85 → 直接拒答，不调 LLM  │
├─────────────────────────────────────────────────────┤
│ 组装 Prompt：System Prompt + 3 块完整文本 + 问题      │
├─────────────────────────────────────────────────────┤
│ Qwen3-8B 生成（temperature=0.3, thinking off）        │
├─────────────────────────────────────────────────────┤
│ 【第二层拒答】LLM 判定资料不足 / 问题过宽 → 拒答句     │
├─────────────────────────────────────────────────────┤
│ 输出回答 + 【教材 p.XX】页码引用                      │
└─────────────────────────────────────────────────────┘
```

**核心设计决策**：检索用两路混合（向量管语义、词汇管精确），拒答用两层加词汇通道（阈值拦无关、词汇放行强证据、LLM 拦"相关但没覆盖"）。设计原则是**每一层都能被单独验证、单独归因**——出了问题能立刻定位是哪一层掉链子，而不是黑盒调参。

## 二、分块策略及理由

### 策略
1. **按书签章节切优先**：PDF 有 209 条书签，`get_toc()` 读出后逐页标注所属章节，章节变化即切块。
2. **章内硬切兜底**：单章超过 3500 字符时按字符切分，块间保留 300 字符重叠。
3. **短块合并**：不足 200 字符的碎片并入前一块。
4. **元数据齐全**：每块记录 `chunk_id / text / page_start / page_end / chapter`。

### 为什么这样切
- **菜谱书天然"一菜一章"**：一道菜的配料表 + 步骤是一个不可分割的语义单元。按章节切，保证 LLM 拿到的块里有完整的配料和做法；若按固定 500 字硬切，极可能出现"配料在块 A、步骤在块 B"，回答必然残缺。
- **实测验证**：159 块覆盖 142 章节，137 章为单块（87%），只有 5 个长章节（FAQ、营养表等）被二次切分。
- **3500 字符的上限依据**：全书最长块 3501 字符，若上限更低会制造更多跨块菜谱；若更高，reranker 对长文本打分会被稀释。

### 一个被数据推翻的假设
我们最初把"按字符切 500 字"当作标准做法（骨架文档也这么建议）。实际跑完发现：菜谱书里同一道菜的做法常跨 2 页，500 字硬切会让问答准确率明显下降。**最终采用"章节优先 + 字符兜底"，这是被语料结构逼出来的设计，不是拍脑袋。**

### 分块粒度的对比实验（回应 800~1200 tokens 要求）

作业文档要求"每块 800~1200 tokens 或等效粒度"。我们的平均块长是 475 tokens，低于该区间，因此专门做了 A/B 实验来验证这是缺陷还是合理取舍：

| 组别 | 策略 | 块数 | 平均块长 | 准确率 | 页码定位 |
|------|------|------|---------|--------|---------|
| A（采用） | 章节切 | 159 | 475 tokens | **89.7%** | **93.1%** |
| B（对照） | 合并到 800 tokens | 93 | 864 tokens | 78.6% | 85.7% |

**结论**：合并切全面下降（准确率 -11.1pp、页码定位 -7.4pp），因为凑够 800 tokens 必须把 2~3 道菜塞进一块，模型会串味、页码会错位。故保留章节切，依据是文档中的"**等效粒度**"——菜谱"一菜一章"的天然语义单元恰好是 475 tokens。

完整实验见 `docs/对比实验_分块粒度.md`。

## 三、Embedding 与检索设计

### 模型选型
| 组件 | 模型 | 参数 | 理由 |
|------|------|------|------|
| Embedding | BAAI/bge-m3 | 1024 维，8192 token | 多语言、长文本、SiliconFlow 免费层 |
| Reranker | BAAI/bge-reranker-v2-m3 | 交叉编码器 | 与 bge-m3 配套，精排 top-3 |
| 生成 | Qwen/Qwen3-8B | temperature=0.3，关闭 thinking | 免费、中文稳定、可控性高 |

### 混合召回为什么必要
纯向量检索对**表格碎片**极不敏感。实测 i17（"一 cup 有多少 tbsp"）：
- 正确块（p.14 单位换算表）被 embedding 召回了，但 reranker 只给 **0.1746**
- 原因：表格提取成文本后是 `3 tsp 1 tbsp 8 tbsp 1 cup 16 oz 1 lb` 这种碎片串，交叉编码器判断"与自然语言问题的相关度"时非常保守

于是增加第二路 **IDF 加权词汇召回**：
```
score = Σ(IDF(命中的实词)) / Σ(IDF(查询全部实词))
```
罕见词（如 satay、tablespoons）命中时权重天然更高。两路各自取 top-20 合并去重，再统一送 reranker。

### 阈值校准：一个"调参无用"的实证
`calibrate_threshold.py` 扫描 0.1~0.9：

| 阈值 | 总正确率 | 课内回答率 | 课外拒答率 |
|------|---------|-----------|-----------|
| 0.1~0.3 | 87.5% | 88.9% | 85.7% |
| 0.4 | 84.4% | 83.3% | 85.7% |
| 0.5 | 87.5% | 83.3% | 92.9% |
| 0.8 | 87.5% | 77.8% | 100.0% |

**0.1~0.3 三档指标完全相同**，说明误判根本不发生在阈值层（而在 LLM 层与数据管道）。脚本机械推荐 0.1，我们判断采用它只会牺牲鲁棒性、带来零收益，**最终保留 0.3**。这个决定后来被证明是对的：真正的提升来自修 bug，不是调阈值。

## 四、Prompt 设计

### 最终版 System Prompt
```
你是基于《The Anabolic Cookbook 2.0》回答问题的助手。严格遵守以下规则：
1. 只能使用【资料】提供的内容作为事实依据，绝对禁止使用内部知识补充数字、用量、步骤或结论。
2. 拒答判定分三种情况：
   a) 【资料】与问题完全无关 → 只输出：根据教材内容未找到相关信息。
   b) 【资料】只有部分相关内容 → 基于相关部分回答，并明确指出资料中未覆盖的部分，不得用常识补全。
   c) 问题没有指明具体菜品、食谱或参数，无法确定回答哪一条（如"怎么做菜""该吃什么"）
      → 只输出：问题过于宽泛，请指明具体食谱或菜品。
3. 每个事实性陈述后标注页码，格式【教材 p.XX】；跨页用【教材 p.XX-YY】。
4. 用简洁中文回答，专业术语可在括号中保留英文原词（如 乳清蛋白(whey)），禁止中英拼接造词。
5. 以转述为主：不得连续照抄资料原文超过 2 句，不得整段罗列原步骤，应概括要点。
6. 必须紧扣提问中的具体对象作答，不得自行挑选一个菜谱代答；回答末尾用一句话点明来源章节。
```

### 设计要点（每条都对应一次实测故障）
| 规则 | 触发它的故障 |
|------|-------------|
| 2 分三档拒答 | 初版"资料里没有就拒答"一刀切，导致 FAQ 类"部分相关"问题被误拒（i13 检索分 0.98 却拒答） |
| 2c 模糊问题 | v01"怎么做菜"被答成"土豆做法"（检索分 0.81），模型自行挑了一道菜 |
| 4 禁中英拼接 | 曾输出"一份水melon（西瓜）"这种病句 |
| 5 禁整段抄 | 首轮 lasagna 回答整段照抄步骤原文，违反 R6 |
| 6 紧扣具体对象 | 与 2c 同源：防止模型"替用户选一道菜" |

### 资料注入格式
```
【教材p.23｜章节：Protein Bread French Toast｜相关度=0.9935】
<完整块文本，不截断>
```
**这里曾经埋了一个大坑**：早期版本写的是 `chunk['text'][:2000]`，而全书 38% 的块超过 2000 字符。结果就是"检索完全正确、LLM 却看不到答案"。详见第七节失败案例 1。

## 五、拒答机制

### 三层防线
| 层级 | 触发条件 | 实现 | 拦得住 | 拦不住 |
|------|---------|------|--------|--------|
| 第一层：阈值 | reranker top1 < 0.3 **且** 词汇分 < 0.85 | `ask()` 前置判断 | 完全无关问题（实测 0.001~0.06） | 语义相关但未覆盖的诱导题 |
| 第二层：LLM | 读资料后判定资料不足/问题过宽 | System Prompt 规则 2 | 诱导题（品牌推荐、宏量计算） | 部分相关的边缘问题 |
| 词汇通道（放行） | 词汇分 ≥ 0.85 | 绕过阈值直接交 LLM 判断 | —— | 会放大 LLM 层压力 |

### 为什么需要"词汇放行"这条反向通道
只往下压阈值会误伤表格类课内题（i17 的 reranker 只有 0.17）。但直接把阈值降到 0.17 会放进大量诱导题。**词汇分是独立的第二信号**：当查询实词几乎全部命中某个块时，即使 reranker 保守，也值得让 LLM 看一眼。

### 实测：为什么 0.85 不能再低
| 题目 | 应判 | 词汇分 | 结论 |
|------|------|--------|------|
| i18 沙嗲蘸酱配料 | 应答 | 0.700 | 误拒（已知限制） |
| a03 怎么算宏量 | 应拒 | 0.699 | 正确拒答 |

两者只差 **0.001**。任何门槛都无法同时满足，最终选择保守值 0.85：宁可误拒 1 道课内题，也不放行诱导题。**"拒答正确率"是课程硬指标，保守优先。**

### 阈值 0.3 的由来
课内题分数 0.177~0.9998，课外题 0.0011~0.8118。中间没有干净的空白带（0.4~0.8 区间两方都有样本），单靠阈值必然有交叉。0.3 是在"课程硬指标优先"原则下的选择，配合 LLM 层兜底。

## 六、评测结果

### 评测集构成（50 条）
| 题型 | 数量 | 占比 | 设计意图 |
|------|------|------|---------|
| in_scope | 30 | 60% | 覆盖早餐/蛋/煎饼/玛芬/前菜/三明治/wrap/米饼/披萨/主菜/甜点/营养表/FAQ 共 13 个板块 |
| out_of_scope | 10 | 20% | 编程、地理、物理、汽修、天气、体育、音乐、文学、自行车、股票 |
| adversarial | 5 | 10% | 类固醇、蛋白摄入量、宏量计算、蛋白粉品牌、生酮——**话题贴近但书里没有** |
| vague | 5 | 10% | 怎么做菜、该吃什么、这本书好吗、说点什么、健康吗——**故意不给具体对象** |

每题带 `gold_pages`（正确页码）与 `gold_keywords`（中英双语标准答案要素），支持自动判定拒答正确性、答案覆盖度、页码准确度。另设 5 条 holdout（`holdout.jsonl`，含 1 条库外陷阱题）供答辩现场抽问，不参与调优，**实测 5/5 通过**。

### 最终指标（50 题，严格口径，2026-10-18）

| 指标 | 数值 | 达标线 | 判定 |
|------|------|--------|------|
| **准确率**（correct/(correct+wrong+hallucinated)） | **89.7%（26/29）** | ≥70% | ✅ |
| **拒答正确率**（refuse_correct/(refuse_correct+refuse_wrong)） | **85.7%（18/21）** | ≥70% | ✅ 硬指标 |
| 课内题回答率 | 96.7%（29/30） | — | — |
| 页码引用覆盖率 | 100%（29/29） | — | — |
| 页码定位准确率 | 93.1%（27/29） | — | — |
| 标准要素全覆盖率 | 79.3%（23/29） | — | — |
| 幻觉条数 | 2 | <3 | ✅ |

分类型：课内 86.7%（26 correct / 1 wrong / 2 hallucinated / 1 误拒）｜课外 100%｜诱导 100%｜模糊 60%

评测集配比：30/10/5/5 = 60%/20%/10%/10%，满足脚手架硬性要求；另设 5 条 holdout 供答辩现场抽问。

### 三轮 A/B 记录
| 轮次 | 改动 | 拒答正确率 | 课内 | 课外 | 页码 |
|------|------|-----------|------|------|------|
| R1 | 基线（纯向量 + 单阈值） | 87.5% | 88.9% | 85.7% | 93.8% |
| R2 | 混合召回 + Prompt 重写 | 87.5%（**零提升**） | 88.9% | 85.7% | 100% |
| R3 | 修复 context 截断 bug | **93.8%** | **94.4%** | **92.9%** | 100% |

**R2 零提升是本项目最重要的发现**：我们加了一整套混合召回，指标纹丝不动。复盘后才意识到，瓶颈压根不在召回侧——召回一直是对的，是组装 context 时把答案截掉了。**指标不动的时候，先查数据管道，再怀疑算法。**

## 七、失败案例分析（3 例真实现场）

### 失败 1：context 截断把答案切掉了（最贵的一个 bug）
- **现象**：i17"一 cup 多少 tbsp"被拒答；i13"guar gum 能换什么"reranker 给 0.98 高分也被拒答。
- **排查路径**：先怀疑召回（查 top-20，正确块在里面）→ 再怀疑 reranker（正确块排第一）→ 最后打印实际喂给 LLM 的 context，发现 **p.13-15 的块末尾被删掉了**。
- **根因**：`context_parts.append(chunk['text'][:2000])`。全书 61 个块（38%）超过 2000 字符，单位换算表恰好位于长块末尾。
- **修复**：去掉截断（最长块 3501 字符，3 块 ≈ 10.5k 字符，Qwen3-8B 的 32k 上下文完全吃得下）。
- **教训**：RAG 的失败有 80% 不在模型。养成"打印最终 prompt"的习惯，比调任何参数都有效。

### 失败 2：模型用世界知识覆盖了原文（R2 边界违规）
- **现象**：i08 瑞典肉丸，原文明确写 `ground turkey`（火鸡），回答写成"鸡肉或牛肉"。
- **根因**：瑞典肉丸的常识做法是牛肉+猪肉，模型的先验知识压过了资料原文。这属于 R2"禁止内部知识"的隐蔽违规——它不编造数字，而是**替换实体**，很难靠数值校验发现。
- **影响**：页码引用是对的（p.117），但配料是错的，属于"引对了页、说错了料"。
- **改进方向**：Prompt 增加"食材名称必须与原文逐字一致"；生成后做实体抽取比对（NLP 侧校验），而不是只依赖 Prompt 自觉。

### 失败 3：PDF 表格结构丢失导致数值错误
- **现象**：i17 答"1 cup = 16 tbsp"（正确答案 8 tbsp）。同一题在不同轮次还答出过 8，说明稳定性差。
- **根因**：PyMuPDF `get_text()` 把两列对照表压成一行连续文本：
  ```
  3 tsp | 1 tbsp | 8 tbsp | 1 cup | 16 oz | 1 lb
  ```
  行列关系丢失后，模型只能猜配对关系，把 `16 oz` 错配给了 `tbsp`。
- **影响**：数值差 2 倍；13 页营养表（卡路里/蛋白质）同样受影响。
- **改进方向**：对表格页改用 `page.find_tables()` 保留行列结构；或把换算表/营养表单独抽成结构化 JSON，作为"事实卡"直接注入 context。

### 附加边界：i18 与 v03
- **i18**（沙嗲蘸酱）：词汇分 0.70，未过 0.85 放行线 → 误拒。根因是修饰词 "dipping" 在书中未以该形态出现，拖低了加权覆盖率。已知限制，不改门槛（见第五节）。
- **v03**（这本书好吗）：主观评价类，系统基于前言做了内容概述。未编造，但不符合"应拒答"预设。判定为可接受的边界偏差。

## 八、如果再做一次会改什么

1. **表格结构化是第一优先级**：换算表 + 13 页营养表是这本书的"高价值事实区"，占我们 2/3 的失败案例。正确做法是建库阶段就用 `find_tables()` 抽成 `{行, 列, 值}` 结构，独立成块并标注 "表格" 类型。
2. **把"打印最终 prompt"做成常规动作**：这次的截断 bug 靠肉眼查 context 才发现。应该在任何指标异常时，第一步就 dump 实际输入。
3. **评测判分升级为 LLM-as-judge**：当前的关键词判定会漏掉"意思对了但用词不同"的情况（比如 zucchini 被译成"西葫芦"以外的说法）。用 LLM 判分 + 人工抽检 20% 更可靠。
4. **实体级校验拦截幻觉**：针对失败 2 这类"替换实体"，可以在生成后抽取食材列表，与 context 原文做集合比对，不一致就打回重生成。
5. **分块增加"块类型"标签**：菜谱 / 表格 / 说明文 三类混合在同一知识库里，reranker 对它们的最佳行为并不一致。分类型检索、分类型阈值会更精细。
6. **评测集再扩容到 80+**：当前 50 题里每个板块约 2 题，仍覆盖不到长尾菜谱。扩充后才能对"改分块策略"这类全局改动做可信的 A/B。

## 十、已知限制清单（答辩可主动说明）

1. 表格类数值问答不可靠（换算表、营养表），需人工复核
2. 词汇门槛 0.85 会误拒"个别罕见修饰词"的课内题（i18）
3. 主观评价类问题未纳入拒答（v03）
4. 关键词判分无法识别同义表述，准确率可能被低估
5. 单轮问答，不支持多轮追问上下文
6. **中文提问对数值/表格类问题失效**：做法类中文提问检索分 0.95~0.996（与英文几乎无差），但单位换算/营养数值类比（0.02~0.05）会被拒答——中文词无法与英文表格文本建立词汇对应，词汇召回归零，仅剩向量一路且向量对表格本就弱。建议数值类问题用英文提问
