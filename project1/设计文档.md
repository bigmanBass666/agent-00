# 项目一设计与复盘文档：课程知识问答智能体（RAG）

> 课程：专业素养培养 / 智能体设计与应用
> 项目占比：25% | 课时：1-3
> 知识库：《操作系统》进程章节（样例语料 3 小节，待替换为教师提供完整版）

---

## 一、系统架构

```
用户提问
   │
   ▼
┌─────────────────────────────────────────────┐
│  第一层拒答：reranker 最高相关度 < 0.5 ?     │
│  是 → 直接输出拒答句，不调用 LLM             │
│  否 ↓                                        │
├─────────────────────────────────────────────┤
│  检索（两段式）                              │
│  ① bge-m3 embedding 余弦相似度粗召回 top-20 │
│  ② bge-reranker-v2-m3 精排取 top-3          │
├─────────────────────────────────────────────┤
│  组装 Prompt：System Prompt + 资料 + 问题    │
├─────────────────────────────────────────────┤
│  LLM 生成（Qwen3-8B，temperature=0.3）      │
│  第二层拒答：资料不足时 LLM 输出拒答句       │
├─────────────────────────────────────────────┤
│  输出回答 + 来源段落编号                     │
└─────────────────────────────────────────────┘
```

核心设计决策：**检索用两段式，拒答用两层**。embedding 负责快速缩小范围，reranker 负责精确排序；阈值拦掉完全不相关的问题，LLM 拦掉"相关但资料没覆盖"的诱导题。

## 二、分块策略及理由

### 策略
1. **按标题切优先**：语料以 `【1.1 进程的概念】` 格式组织，用正则 `(?=【\d+\.\d+)` 前瞻断言切分，每个标题段落天然是一个语义完整单元。
2. **硬切兜底**：若单个段落超过 `CHUNK_SIZE=500` 字，按固定长度硬切，块间保留 `CHUNK_OVERLAP=50` 字重叠，防止句子在边界被截断。
3. **来源标记**：每个 chunk 记录 `chunk_id`、`text`、`source`（所属标题），用于回答末尾标注来源。

### 理由
- **标题切优于纯固定长度切**：标题边界是作者设定的语义分隔点，比任意 500 字切分更能保持知识完整性。
- **重叠的必要性**：即使硬切，50 字重叠确保关键概念不会恰好落在两个块的缝隙里。
- **当前语料仅 3 小节（共约 300 字）**，未触发硬切逻辑；待教师提供完整 3 章语料后，硬切+重叠会生效。

### 与标准分块的一致性
对照 `13_样例语料与标准分块.md`，本方案的分块结果与标准分块完全一致（chunk 0/1/2 分别对应 1.1/1.2/1.3）。

## 三、Embedding 与检索设计

### 模型选型
| 组件 | 模型 | 维度 | 理由 |
|------|------|------|------|
| Embedding | BAAI/bge-m3 | 1024 | 多语言、8192 token 长文本、密集+稀疏+多向量，SiliconFlow 长期免费 |
| Reranker | BAAI/bge-reranker-v2-m3 | — | 与 bge-m3 官方搭配，跨编码器精排，免费 |

### 两段式检索
1. **粗召回**：query 经 bge-m3 向量化后，与全部 chunk 向量计算余弦相似度（向量已 L2 归一化，点积即余弦），取 top-20。
2. **精排**：将 top-20 候选文本连同 query 传给 bge-reranker-v2-m3，返回精确相关度，取 top-3 喂给 LLM。

### 为什么需要两段式
- 单段 embedding 检索：速度快但语义区分粒度粗。
- 全量 reranker：精确但慢。
- 两段式结合：embedding 先把范围从几百缩到 20，reranker 再从 20 里挑 3，兼顾速度和精度。

### 哈希 Embedding 对比实验（基线）
| 问题 | 哈希版 top_score | bge-m3+reranker top_score | 哈希版结果 |
|------|-----------------|--------------------------|-----------|
| 进程有哪几种状态？ | 0.2918 | 0.9986 | 哈希版误拒答 |
| 什么是进程？ | 0.3982 | 0.9993 | 勉强通过 |
| 明天天气怎么样？ | 0.1561 | 0.0000 | 均拒答 |

结论：哈希 embedding 语义区分能力极弱，课内题与库外题分数重叠严重。bge-m3 将课内题拉到 0.71~0.99，库外题压到 0.00~0.01，分离度提升一个数量级。

## 四、Prompt 设计

### 最终版 System Prompt
```
你是课程助教。请依据【资料】回答问题，答案必须来自资料内容。
只有当资料中完全没有相关信息时，才输出且仅输出：课程资料中未找到相关内容。
回答末尾注明来源段落编号。
```

### A/B 迭代记录
| 版本 | Prompt 关键句 | 拒答正确率 | 问题 |
|------|-------------|-----------|------|
| A | "你只能依据【资料】回答，不得编造。若资料不足以回答，必须只输出：拒答句" | 75.0% | 3 条课内题被误拒答，模型在正确回答后又 append 拒答句 |
| B | "请依据【资料】回答，答案必须来自资料。只有当资料中完全没有相关信息时，才输出且仅输出：拒答句" | 100.0% | 0 条误拒答 |

### 改动要点
1. "只能依据"→"请依据"：降低命令式压迫感。
2. "若资料不足以回答"→"只有当资料中完全没有相关信息时"：明确拒答触发条件。
3. "必须只输出"→"才输出且仅输出"：强调拒答句是唯一输出。
4. 检测逻辑从 `in ans` 改为 `startswith(REFUSE_SENTENCE)`：防止答完又 append 被误判。

### 其他参数
- `temperature=0.3`：课程问答需准确性，低温度。
- `enable_thinking=False`：关闭推理模式，严格执行拒答约束。

## 五、拒答机制

### 两层拒答架构
| 层级 | 触发条件 | 实现方式 | 能拦住什么 | 拦不住什么 |
|------|---------|---------|-----------|-----------|
| 第一层（前置） | reranker 最高相关度 < 0.5 | rag_query() 中判断 | 完全不相关的问题 | 语义相关但资料没覆盖的诱导题 |
| 第二层（LLM） | LLM 读资料后判断完全没有相关信息 | System Prompt 约束 | 诱导题（线程、五种状态、PCB） | — |

### 阈值选择依据
实测分数分布呈极端双峰：课内/相关题 0.71~0.99，库外/无关题 0.00~0.01。中间存在巨大空白带，阈值取 0.5 稳稳落在空白带中央。

### 为什么第一层拒答放在 LLM 之前
1. **省 token**：明显无关的问题不调 LLM。
2. **防编造**：低相关资料喂给 LLM，模型可能"认真地编造"。

## 七、失败案例分析（3 例）

### 失败案例 1：哈希 Embedding 导致课内题误拒答
- 现象："进程有哪几种状态？"top_score=0.2918 < 阈值 0.35，被前置拒答。
- 根因：哈希 embedding 仅统计字符 n-gram 重叠，无语义理解。
- 修复：替换为 bge-m3，分数升至 0.9986。
- 教训：embedding 质量是 RAG 基石，占位方案只能调试链路。

### 失败案例 2：LLM 过度保守导致课内题误拒答（Prompt 版本 A）
- 现象：q02/q06/q14 三条课内题，LLM 生成正确答案后又 append 拒答句。
- 根因：Prompt 表述模糊 + 检测逻辑 `in ans` 过于粗暴。
- 修复：Prompt 改为"只有完全没有相关信息时才拒答" + 检测改为 `startswith`。
- 结果：拒答正确率 75.0% → 100.0%。

### 失败案例 3：诱导题绕过前置阈值（Mock LLM 阶段）
- 现象：q21"进程和线程的区别"（0.7134）、q22"进程的五种状态"（0.9870）通过阈值并被 mock"作答"。
- 根因：语义相关导致 reranker 分数高，前置阈值无法拦截；mock_llm 不读资料。
- 修复：接入真实 LLM，模型读资料后发现未覆盖，正确拒答。
- 教训：相似度只能判断"像不像"，不能判断"够不够回答"，第二层 LLM 拒答不可或缺。

## 八、如果再做一次会改什么

1. **语料预处理自动化**：写脚本从 PPT/Word 自动提取并标准化为 `【x.x】` 格式。
2. **Embedding 缓存**：语料不变时加载本地 `.npy` 缓存，启动从秒级降到毫秒级。
3. **评测集扩充**：完整语料到位后扩充到 50+ 条，增加跨章节综合题和表述歧义题。
4. **阈值数据驱动调优**：用网格搜索在评测集上找最优阈值，而非经验设定。
5. **答案后处理**：截断"正确回答末尾 append 拒答句"的瑕疵部分。
6. **流式输出**：答辩演示时改为流式输出，提升交互体验。
