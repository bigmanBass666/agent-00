# RAG 概念卡（8 张）

**用法**：每张卡的正确顺序是 ①跑通例子 → ②读定义 → ③组内互讲（讲不清”它不解决什么问题”不算掌握）。卡点超过 30 分钟记入会议纪要。

## 卡 1：LLM 是什么

**一句话**：LLM 是从海量文本中学习”下一个词概率”的模型，它记住的是语言的统计模式，不是数据库。

**最小例子**：问模型你的课程表——它答得头头是道但全是编的，因为它没有你的课程表数据。

**常见误区**：以为模型”知道”某门课的内容。不知道，除非你把资料喂给它（这就是 RAG 存在的理由）。

## 卡 2：Token 与上下文窗口

**一句话**：Token 是模型处理文本的最小单位（约 0.7 个汉字 / 0.75 个英文单词），上下文窗口是模型一次能”看到”的最大 token 数。

**最小例子**：课程教材 5 万字约 7 万 token，超过了大多数模型的单次输入上限——所以不能整本书塞进去问，只能先检索出相关段落。

**常见误区**：按”字”估算 token。应使用分词器工具（如 tiktoken 或在线 tokenizer）实际计算。

## 卡 3：Prompt 结构

**一句话**：Prompt = 系统指令（角色与规则）+ 上下文（检索到的资料）+ 用户问题 + 输出格式要求。

**最小例子**：系统指令”你是课程助教，只能依据给定资料回答”；上下文放检索段落；输出要求”回答后注明来源段落编号”。

**常见误区**：把所有资料拼进 Prompt 而不筛选——既贵又稀释注意力。检索的意义就是只放最相关的几段。

## 卡 4：Embedding（文本向量）

**一句话**：Embedding 把一段文本映射为固定长度的数字向量，语义相近的文本向量距离也近。

**最小例子**：“进程调度”和”CPU 分配算法”字面不同但向量距离近；和”食堂菜谱”距离远。检索靠的就是这个距离。

**常见误区**：向量近 ≠ 答案就在里面。向量模型衡量语义相似，不衡量”是否包含答案”，所以检索后仍需评估相关性。

## 卡 5：向量数据库

**一句话**：向量数据库是按向量距离快速检索的存储系统；本项目用小规模数据，本地文件（FAISS/Chroma）足够。

**最小例子**：1000 个分块存入 Chroma，查询时返回 top-3 最近向量对应的分块。

**常见误区**：以为必须用专业向量数据库。几千个分块用 numpy 暴力算距离也只要几十毫秒——工程选型要跟数据规模走。

## 卡 6：RAG 流程

**一句话**：提问 → 检索（embedding 查询 → top-k 分块）→ 组装 Prompt → LLM 生成 → 输出来源。这五步是本项目的骨架。

**最小例子**：见 `12_最小RAG骨架.py`，代码结构与这五步一一对应。

**常见误区**：以为 RAG 能自动消除幻觉。检索错段落时模型会”认真地引用错误资料”，所以必须同时设计拒答机制（卡 8）。

## 卡 7：分块策略（Chunking）

**一句话**：分块是把长文档切成检索单元的过程；块太大稀释精度，太小断章取义。

**最小例子**：按固定 500 字切，会把”进程的定义是……其特点是……“切断在两个块里。按标题/段落切能保持语义完整。

**常见误区**：只调块大小不看重叠（overlap）。块间重叠 10–15% 可缓解边界切断问题，但会增大数据量，需权衡。

## 卡 8：幻觉与拒答

**一句话**：幻觉是模型生成与事实不符的内容；拒答机制让系统在”没有把握”时明说”不知道”，这是本项目验收的核心指标。

**最小例子**：设置相似度阈值——检索最高分低于阈值时，不调用生成，直接返回”课程资料中未找到相关内容”。

**常见误区**：以为 Prompt 里写”不要编造”就够了。指令只是软约束，必须用阈值、过滤、评测三件套硬约束，并用评测集验证拒答率。
