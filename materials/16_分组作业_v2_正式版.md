# 某课程知识库的智能问答系统 · 分组实践作业（v2 正式版）
2026-2027学年第1学期  |  专业素养培养
## 一、作业背景
在人工智能时代，基于检索增强生成（RAG, Retrieval-Augmented Generation）技术的智能问答系统能够基于特定知识库回答问题，有效避免大语言模型的“幻觉”问题。RAG 的核心思想是：先从知识库中检索与问题相关的内容，再基于检索结果生成回答，而非直接依赖模型的内部知识。
本作业要求各小组选择一门课程的教材，构建本地知识库，并配置一个只基于教材内容回答问题、附带页码引用的智能问答系统。通过完整实施这一过程，深入理解 RAG 技术的工作原理与工程实践。
本作业强调“约束行为、开放实现”：对 RAG 合规行为提出强制要求，但对具体技术栈不做限定，鼓励各小组选择不同的技术路线实现。
## 二、参考案例
教师已提供一个完整参考实现——“计算机网络 RAG 智能体问答系统（CN-Tutor）”，基于《Computer Networking: A Top-Down Approach》第8版教材构建。
参考实现的技术方案（仅作示例，非强制要求）：
知识库：Python + PyMuPDF + SQLite FTS5（trigram tokenizer, BM25 排序）
智能体：DSH (DeepSeek Harness) 框架 + 自定义插件
核心机制：toolOrder 确保先检索后回答，五段系统提示词约束 RAG 行为
参考文档：CN-Tutor_RAG系统实施过程.pptx（18页实施指南）
各小组可参考该实现的 RAG 设计思路与工程结构，但需选择不同的课程教材，并鼓励采用与参考案例不同的技术栈实现。
## 三、强制行为要求（与技术栈无关）
无论采用何种技术栈，系统必须满足以下 RAG 行为约束：
| 编号 | 行为要求 | 验证方式 |
|---|---|---|
| R1 | 回答任何课程问题前，必须先检索知识库 | 检查系统日志/调用记录中检索先于回答 |
| R2 | 只能使用检索到的教材内容作为事实依据，禁止使用模型内部知识 | 提问教材未覆盖的问题，检查是否回答“未找到” |
| R3 | 每个事实性陈述必须附带教材页码引用，格式为【教材 p.XX】 | 检查回答中每个事实后是否有页码标注 |
| R4 | 用简单中文解释，关键术语保留英文原文 | 检查回答语言风格与术语处理 |
| R5 | 检索未覆盖的内容必须如实说明，不得编造或推测 | 提问边缘问题，检查是否诚实标注未覆盖部分 |
| R6 | 禁止直接输出教材大段原文（版权保护），只允许短句引用和转述 | 检查回答中无超过 3 句的连续原文复制 |

## 四、任务要求
各小组需完成以下两个阶段的全部工作：
## Phase 1 — 知识库构建（技术栈自选）
选择一门课程的教材（PDF 格式，不少于 100 页，含清晰章节结构）
提取每页文本并保留页码元数据（工具自选：PyMuPDF / pdfplumber / PDFMiner 等）
检测章节边界（不少于 3 个章节），可利用 PDF 书签或正则匹配
按章节进行语义分块（每块 800~1200 tokens 或等效粒度，块间有重叠）
构建全文检索或向量检索知识库（方案自选，见第五节技术栈选项）
每个文本块需记录：text, page_start, page_end, chapter 信息
验证知识库：检索测试、块数统计、章节覆盖率检查
## Phase 2 — 智能问答系统配置（技术栈自选）
选择并搭建智能体框架（见第五节技术栈选项）
实现 knowledge_search 检索工具/函数，查询本地知识库并返回带页码的片段
设计系统提示词，确保 R1~R6 行为约束全部生效
配置工具调用优先级或 RAG 流程，确保检索先于回答
进行至少 3 个问题的冒烟测试，验证 RAG 合规性（对照第三节 R1~R6）
## 五、技术栈选项（四选一或自定）
各小组从以下方案中选择一种，或提出自定义方案（需经教师确认）。鼓励不同小组选择不同方案，促进技术多样性。
| 方案 | 知识库 | 智能体 / RAG 框架 | 检索方式 | 难度 | 适合背景 |
|---|---|---|---|---|---|
| A（参考路径） | SQLite + FTS5 (PyMuPDF 分块) | DSH 框架 + 自定义插件 | FTS5 全文检索 + BM25 排序 | 中 | 有 Node.js / JS 经验 |
| B | ChromaDB / FAISS (向量库) | LangChain 或 LlamaIndex | Embedding 向量 检索 + Top-K | 中高 | 有 Python / ML 经验 |
| C | SQLite + FTS5 (纯 Python) | 直接调用 LLM API (OpenAI / DeepSeek) | FTS5 全文检索 + 自定义 prompt | 低中 | 有 Python 基础 入门友好 |
| D | 内置知识库 (平台管理) | Dify / FastGPT / 其他低代码平台 | 平台内置检索 (向量/全文) | 低 | 无编程经验 快速搭建 |

## 方案说明：
方案 A 为教师参考案例使用的技术栈，有完整实施指南可参考
方案 B 使用主流 RAG 框架（LangChain / LlamaIndex），生态成熟，适合有 Python ML 基础的同学
方案 C 从零搭建，直接调用 LLM API + 自定义检索逻辑，理解最深入
方案 D 使用低代码平台快速搭建，重点放在知识库质量与 RAG 行为验证
自定义方案：可组合上述方案的组件，或使用其他框架（Haystack / txtai / Weaviate 等），需经教师确认

## 十、注意事项
教材 PDF 需为合法获取的电子版，不得使用盗版资源
无论采用何种技术栈，R1~R6 行为约束必须全部满足
每个事实性陈述必须附教材页码引用，格式为【教材 p.XX】
教材未覆盖的内容必须如实说明“未找到”，不得编造或推测
禁止直接输出教材大段原文（版权保护），只允许短句引用和转述
知识库的 tokenizer / embedding 模型需适配教材语言（英文 / 中文 / 双语）
使用 LLM API 的小组需自行管理 API Key，不得在代码或提交物中暴露密钥
如选择方案 A（DSH），可参考 CN-Tutor 实施指南；选择其他方案需自行查阅框架文档
## 十一、拓展挑战（选做，加分）
实现多语言支持：知识库同时包含中英文教材，检索时自动切换
实现多轮对话：智能体能理解上下文中的指代关系（如“它”“该协议”）
实现知识库增量更新：支持向已有知识库追加新章节或新教材
实现混合检索：同时使用全文检索 + 向量检索，融合排序
实现检索结果重排序：使用交叉编码器（cross-encoder）对初检结果二次排序
实现可视化界面：为智能体添加 Web UI 或命令行交互界面
对比实验：用同一教材对比不同技术栈（如 FTS5 vs 向量检索）的检索质量
每完成一项拓展挑战加 2~5 分，总分不超过 100 分。
